# OceanTrace: PS 26143 system audit, 2026-09-18

This audit checks, against the code, whether OceanTrace implements the workflow
SIH problem statement 26143 asks for. It covers what runs for real, what is
synthetic, what is missing, and which connections were broken and have now been
fixed. Every "evidence" cell points at code or at an artefact of a sealed run.
Docs were not taken on trust.

**Verdict: functional end to end, with honest gaps.** A Sentinel-1 scene goes
through detection, characterisation, hindcast and forecast, AIS reconstruction,
and gated, weighted attribution to an investigator workspace and a report. All of
it runs for real on the frozen flagship (`inv-gulf-flagship-20230108-2day`,
MarineCadastre AIS, CMEMS + ERA5 forcing). The audit found four defects that
changed what the system *claimed*: §3 items 1–4. A fifth, item 5, silently lost
live AIS data. All five are fixed and covered by tests.

## 2. Connection trace (flagship)

```
S1A GRD (CDSE) ─ calibrate ─▶ scene_sigma0_db.tif
  └─ detect ─▶ detect_response.json (392 candidates: 31 oil, 361 look-alike) + raw_mask.tif
       └─ characterise (Engine A) ─▶ slick.geojson (62 regions, largest first)
            └─ drift (Engine B, CMEMS + ERA5) ─▶ origin_cloud.geojson (window 11:10→00:10Z, ±0.37 km)
                                              ─▶ forecast.geojson (+6/+12 h, 50/90%)
                 └─ attribution (Engine C, MarineCadastre 86,830 rows) ─▶ suspects.json (32 → 4 ranked)
                      └─ /api/layers/{run}/{layer}, /api/runs/{run}/vessels_geojson,
                         /api/runs/{run}/forcing_field, /api/tiles/{run}/…
                           └─ Workspace: map layers, Brief, Spill, Drift, Suspects; /report
```

A parallel sweep of `lib/api.js` against the FastAPI routers found **no frontend
call to an undefined route**. 29 client methods have no caller. Those are backend
features with no UI yet (decisions loop, run verify, funnel, AOI CRUD, AIS stream
control, auto-incident).

## 3. Defects found and fixed in this audit

1. **Drift and attribution could trace a look-alike.** Characterisation measured the
   segmenter's full mask, and drift seeds from the largest slick. On the flagship, the
   analysed slick `COG_slick_01` sits inside a region the screen **rejected**, as do 49
   of its 62 slick features. The only guard was a warning for the case where *every*
   region was rejected. **Fix:** when the screen splits regions, detect writes an
   oil-only `engine_native/screened_mask.tif` and characterisation measures that;
   `raw_mask.tif` is untouched (`service.py::screen_mask`,
   `run.py::characterise_mask_for`, `test_lookalike_screening.py`). The flagship is
   frozen, so the workspace, brief and report now show **Screen verdict: LOOK-ALIKE**
   for it (`lib/drift.js::screenVerdict`).
2. **The map's "probable origin" was not the run's origin.** The ring sat on the
   ellipse at T−(backtrack/2) with a hard-coded 2.2 km radius. The run publishes a
   window and `origin_uncertainty_km` (0.37 km on the flagship). **Fix:** one helper,
   `originEstimate`, used by the map, the Drift tab, the brief and the report. It
   takes the ellipse nearest the window midpoint and uses the published radius.
3. **The Incident Replay drew fabricated forecast particles.** 160 random points
   around the centroid were pushed by wind alone and drawn in the forecast colour over
   the engine's real envelopes. **Removed.** The forecast shown is Engine B's output only.
4. **The wind/current field shown could differ from the one the drift used.**
   `/forcing_field` re-resolved grids at request time; 1 of the 14 recorded grids in
   the live registry resolved to a different file (Open-Meteo used, ERA5 shown).
   **Fix:** the endpoint finds the grid by the normalisation stamp the run recorded,
   and reports `matches_run` (`test_forcing_field.py`).

5. **Live AIS ingest lost whole batches.** The DB session does not autoflush, so a
   second position from a newly seen vessel in the same drain was inserted twice.
   The UNIQUE violation at commit discarded every position in that batch; identity
   from a same-batch static frame was dropped as well. **Fix:** a per-batch row map in
   `AisLiveWorker._upsert_live` / `_merge_static`. Found because
   `test_archived_rows_are_contract_shaped`, apparently skipped while pyarrow was
   blocked, ran for the first time. The same test file also had fixed-date fixtures
   that aged out of the live-picture window; they are now relative to the current
   time.

Also corrected:
- The Incident Replay showed the rank-1 **score as "66.9% likelihood"**. It now shows "Rank #1 score 0.67" (standing rule 6).
- "Origin conf. 0.9" was the 90% contour level; it now shows "Origin uncertainty ± 0.37 km".
- "Vessels analysed 198" counted every AIS track in the scene; the panel now separates AIS vessels in scene (198), vessels considered by attribution (32) and vessels ranked (4).
- The brief now labels currents and wind with the drift stage's **CACHED** data provenance instead of the engine's REAL flag.
- The panels said "not produced" for layers that were **still loading**, the 430 KB origin cloud in particular. They now distinguish loading from absent (404).
- The report listed "unclassified" 361 times.
- `docs/LIMITATIONS.md` claimed there was no weathering; the forecast does carry a weathering estimate.
- `InvestigationMap.jsx`, imported nowhere, was deleted.

## 3b. The flagship scene re-run with screening (new runs; the flagship itself is untouched)

| | flagship `-2day` (sealed 09-07) | `inv-gulf-screened-2day-20230108` (09-18) |
|---|---|---|
| Characterised slicks | 62 (49 on rejected regions) | **13, all on screen-confirmed oil** (361/361 rejected regions removed) |
| Analysed slick | `COG_slick_01`, 6.83 km², inside a rejected region | `COG_slick_01`, 0.76 km², 27.654° N 90.857° W, oil |
| Origin window | 13 h, peak **at** acquisition (did not localise) | 19 h, peak 2023-01-07 19:10 UTC (**5 h before** the image) |
| Origin uncertainty | 0.37 km | 0.14 km |
| AIS | MarineCadastre, 2 days, real | same two days, real (covers the window) |
| Vessels considered → ranked | 32 → 4 | **30 → 0** |

**The honest outcome on this scene: once drift traces an oil-screened slick, no vessel
in the real AIS passes the gates.** 6 vessels fail only the trajectory gate (course
more than 45° off the slick axis), 3 fail only the spatial gate (origin region + 5 km),
and 21 fail several. The gates are the reasoned thresholds (LIMITATIONS 11) and were
not changed (standing rule 11). The four vessels ranked on the flagship were ranked
against a look-alike's origin. Both runs 5/5 stages real, verify OK, registered via
`backfill_runs`. A sibling run with synthetic AIS, `inv-gulf-screened-20230108`, shows
the fallback when no real archive is staged; it is labelled SYNTHETIC throughout.

## 4. UI changes

- **Workspace right panel: Brief · Spill · Drift · Suspects.** The **Brief** is the
  investigator's first read. It answers what, where, when, how large, where from,
  where to, which vessels, why they rank and what is uncertain, each answer from an
  artefact. Mock or synthetic answers are tagged SYNTHETIC inline. It ends with a
  data-sources block (satellite, AIS, currents, wind) carrying provenance badges.
- **Drift tab.** Hindcast and forecast are colour-separated (magenta and amber, as
  on the map). It shows the window, method, peak and uncertainty; the forecast table
  (horizon, valid time, envelope, area); forcing providers, windage, integrator and
  ML-residual state; weathering at LOW confidence; and the weak-window warning.
- **Spill tab.** Names the analysed slick ("largest of 62") and shows the screen
  verdict, elongation, age method, model and scene metadata (polarisation, pixel
  spacing, provider). The other regions are in a collapsible table.
- **Map.** Wind and current vector layers, off by default, drawn from the exact grids
  the drift integrated, at the timestep nearest the clock. Arrow length is relative
  (stated in the legend). The origin ring uses the published radius, with a
  fixed-size marker on top.
- Picking a vessel on the map opens its evidence in the Suspects tab.
- The report gains Hindcast, Forecast and Data-sources sections, plus age and screen-verdict rows.

## 5. Remaining limitations (not fixed here)

- **EO/Sentinel-2 is not deployed** (declared, 501).
- **The pipeline does not fetch forcing or scenes during a run.** It uses pre-staged
  grids and falls back to sample inputs or mocks, labelled. A run with no scene
  defaults to the demo raster.
- **Indian-waters AIS is synthetic.** AISStream has no Bay of Bengal coverage, and the
  synthetic fleet plants a culprit at the drift origin, which is circular by
  construction. It demonstrates the method; it is labelled SYNTHETIC everywhere.
- **No Stokes drift; flat 3% windage; weathering uses an assumed oil type.**
- **No closest-approach *time*;** `closest_approach_km` is the distance to the origin region.
- **The flagship's window is weak** (13 h, peak at acquisition), and it traced a
  rejected look-alike (§3.1). It is frozen, so this is stated on screen rather than re-run.
- **Pipeline ≈ 225 s on a full-resolution scene** (plan: 60 s). HDF5 is not
  thread-safe; runs are serialised.
- **Backend features with no UI:** analyst decisions, run verify, funnel, AOI CRUD,
  AIS stream control.

- New backend tests: `test_lookalike_screening.py` (7) and `test_forcing_field.py` (3) pass.
